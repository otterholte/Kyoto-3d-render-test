# Canby Court — browser walk + winter sledding game

A third-person, phone-and-desktop experience of Canby Ct, a cul-de-sac off 38th St in Bellingham, WA. You can:

* walk the street and all the way around 3905 Canby Ct;
* switch between **summer** (a July evening, low sun from the WNW) and **winter** (late December, low sun
  through thin overcast, falling snow);
* in winter, ride a sled down the street (134 m, 14.8 m drop) over three snow kickers. Pop at the lip, do
  tricks in the air, and stop in the run-out before 38th St.

It is a static page. three.js r170 and three-mesh-bvh 0.8.3 load from the jsDelivr CDN (exact versions in an
import map). Everything else is relative files in this folder. The architecture reuses the Higashiyama explorer
(`../../web/`): capsule controller with BVH collision and step-up, joystick + drag look, adaptive DPR, PMREM
sky IBL, the GTAO / bloom / AA tiers, photo mode, a watchdog, and GLBs shipped as base64 text.

## Build

```bash
cd canby-court/web
npm install          # dev tools only: gltf-transform, meshoptimizer, sharp, three (tests), http-server
node build.mjs       # = npm run build   (~5 s without world GLBs)
npm run serve        # http://localhost:8766/
npm test             # Playwright: desktop 1440x900 + iPhone 13 + Pixel 7 -> ../docs/web_screens/ + results.json
node tests/views.mjs # docs screenshots (High tier) -> ../docs/web_screens/
```

`build.mjs` does the following:

1. **Terrain.** It decodes `data/processed/terrain/heightmap_u16.png` (0.5 m 3DEP DTM, 16-bit) and writes
   `dist/terrain.u16.b64.txt`. That file is raw uint16 little-endian as base64, because the host serves no
   binary types. The page builds the terrain mesh and collider from it: a tensor grid, 1 m in the core and
   3 m outside, plus a far skirt.
2. **Surface classes.** It converts `data/processed/groundcover/classes_0p3m.tif` into `assets/surface.png`.
   The RGB channels are weights: R asphalt, G concrete, B lawn, and the remainder planting beds. The ground
   shader and the minimap use it.
3. **World data.** It writes `assets/world_data.json`, which holds:
   * houses: footprints, storeys, inferred eave and ridge heights, pitch, ridge bearing, roof colour,
     garage note, and doors from `blender/scene_meta.json` when that file exists;
   * context buildings, trees, hedges, the Canby Ct centreline and pavement polygon;
   * the sled run path, the kickers and the berm from `data/game/jumps.json`.
4. **GLBs.** It processes `assets/world_summer.glb`, `assets/world_winter.glb`, `assets/character.glb` and
   `assets/sled.glb` when they exist. The output is `dist/<name>.glb.b64.txt`.
   * **World GLBs** (scene agent): images stay external, so both seasons share `assets/tex/*.jpg` and the
     texture library is not duplicated. The build does dedup, prune (extras kept) and meshopt (16-bit
     positions, 10-bit normals, 14-bit UVs), then writes the original `tex/…` URIs back into the GLB JSON.
     The page parses it with resource path `assets/`. The images each world references are listed in the
     manifest and the publish list.
   * A GLB that is already meshopt-compressed (as the character and sled are) is shipped byte-for-byte.
   * Any other GLB goes through dedup, prune, WebP textures up to 2048 px, and meshopt.

   `dist/manifest.json` lists only the files that exist, so the page never requests a missing one.
5. **Library textures.** When `assets/tex/library.json` exists, it lists eight of the scene agent's
   photographic sets in the manifest. The placeholder ground and house shaders use them:
   * ground: lawn, asphalt, concrete drive, bark mulch, fresh and packed snow;
   * houses: shingles and lap siding, desktop only.

   The page loads them only while at least one season uses the placeholder world.
6. **`artifact.html`.** It regenerates this file: `index.html` without the html/head/body wrapper, which the
   artifact host adds. Edit only `index.html`.
7. **Publish list.** It writes `dist/publish.txt` with the exact files and sizes to publish.

**Re-run `node build.mjs` whenever the GLBs, `assets/tex` or the data change.**

## Controls

| | desktop | touch |
|---|---|---|
| walk | WASD / arrows (camera-relative), Shift run, Space jump | left thumb: joystick; **Run** toggle |
| look / zoom | drag, mouse wheel | drag on the right, pinch |
| season | ❄ / ☀ button (fade transition) | same |
| sled | **Sled** button near the top of the run (winter) | same |
| steer / brake / paddle | A D or ← →, S, W | left thumb (left/right, down = brake, up = paddle) |
| pop / boost | Space (at the lip) | big **POP** button |
| tricks | 1 Superman, 2 Spread eagle, 3 Grab (in the air) | three trick buttons |
| restart / leave | R / Esc | ↻ Restart / ✕ Walk |

Other UI:

* **Places:** Cul-de-sac bulb (spawn, facing 3905), 3905 front door, 3905 back yard, Top of the sled run,
  Bottom · 38th St.
* **Minimap:** tap it to switch between local and whole-area views.
* **Settings:** quality (Auto / Low / Medium / High) and procedural sound (Web Audio, off until you tap).
* **ⓘ:** sources, what is measured and what is artistic, credits.
* **Photo mode:** hides the UI and switches to the Ultra tier.

## Sled game

The physics and rules live in `src/sled.js`. Tuning is in `src/config.js › SLED`.

* **Physics.** The sled is a point mass on the collider surfaces: snow terrain and kicker meshes, sampled by
  BVH rays, with fixed 1/120 s sub-steps. Forces:
  * gravity along the surface;
  * Coulomb snow friction: μ 0.045 on the packed track, 0.08 off it, plus 0.3 when braking;
  * quadratic air drag;
  * lateral grip: carving keeps about 88 % of the speed, and steering hard above 7 m/s skids, with spray and
    extra friction;
  * lean steering, and hand paddling when slow.
* **Kickers.** At the lip (the end of the ramp along its heading) the sled launches along the lip angle
  measured against the run surface. It also leaves the ground wherever the surface falls away faster than
  gravity can follow.
* **Pop / boost.** One extra impulse per jump, +2.3 to +3.6 m/s. Press it on the ramp (up to 0.35 s before
  takeoff) or up to 0.25 s after takeoff. Timing scores "Perfect pop" (+50 to +200 points).
* **Tricks.** Superman (600 points), Spread eagle (400) and Grab (250) play the character clips, sped up to
  0.95 / 0.8 / 0.6 s. A trick scores only if it finishes before touch-down; a combo adds ×1.5 per extra trick.
  A trick that is less than 85 % done at landing is a wipeout.
* **Wipeouts.** These also count as wipeouts:
  * an impact into the slope above 12.5 m/s;
  * a sideways landing (more than 72° between heading and travel);
  * a crash into a house, trunk or hedge at more than 6.5 m/s.

  The rider tumbles away from the sled, then respawns at the last checkpoint (16 m before each kicker) with
  the speed recorded there.
* **Run-out.** Over the last 18 m before the berm, deep loose snow ramps μ up to 0.55. The berm and hay bales
  absorb anything left. The run ends when the sled stops past the last kicker; reaching 38th St counts as an
  overrun.
* **HUD and camera.** The HUD shows speed, airtime, timer, score, best (in `localStorage`, wrapped in
  try/catch), pop and trick call-outs, run progress with the kicker marks, and a summary at the end of the
  run. The chase cam follows the direction of travel. Its field of view widens with speed, it is looser
  vertically in the air, and it pulls in when the view ray hits geometry. Drag to glance around.
* **Measured in the headless physics run** (autopilot, same colliders as the page):

  | world | big kicker, no pop | big kicker, perfect pop | stops before the 38th St junction |
  |---|---|---|---|
  | scene agent's `world_winter.glb` | 0.93 s air, apex 0.38 m | 1.57 s air, apex 1.76 m | 11 m (top speed 12 m/s, run 19 s) |
  | placeholder | 0.92 s air, apex 0.24 m | 1.5 s air, apex 1.65 m | 12 to 14 m |

## World and look

* **GLB worlds** (`assets/world_{summer,winter}.glb` from the scene agent) are rendered with their authored
  PBR materials.
  * Lights and cameras in the files are dropped.
  * Meshes reused at least 4 times (trees, shrubs, hedges…) become `InstancedMesh`es, which takes about 2,100
    nodes down to a few dozen draw calls.
  * Colliders come from the node extras `collide`, `walkable` and `kind`:
    * walkable surfaces and solid props: their own triangles;
    * trees: a trunk prism of `collide_radius`;
    * hedges: their oriented box;
    * `collide: false` and not walkable (shrubs, snow caps, house numbers): none.
  * Kickers are recognised by name (`Jump_*`, `Berm_*`) or by `kind`. If the winter GLB has none, the page adds
    its own from `jumps.json`. The hay bales (`kind: hay_bales`) absorb the sled.
* **Placeholder world.** Until then, or if a GLB fails to load, the page builds the scene itself from the
  survey data:
  * DTM terrain with a ground shader driven by the surface-class map, using photographic sets when
    available;
  * all 10 Canby Ct houses and the context buildings: footprint walls with lap siding and windows; hip or
    side-gable roofs from the inferred heights, pitch and ridge bearing with real roof colours; doors and
    garage doors from `scene_meta.json`;
  * the 142 trees (instanced):
    * on Medium and up, leaf-card crowns from the scene agent's foliage atlas (fir and cedar sprays,
      snow-laden in winter; maple clusters on branch skeletons in summer, bare branches in winter);
    * on Low, faceted crowns;
  * the 12 hedges;
  * the kickers, berm, hay bales and marker flags.
* **Lighting.**
  * The sun position comes from a solar model for the site: summer 2025-07-20 19:20 PDT, altitude 14.6°,
    azimuth 284°; winter 2025-12-28 13:50 PST.
  * Sun colour follows Kasten–Young airmass transmittance.
  * The sky is a gradient with a cloud deck: scattered cumulus in summer, full overcast in winter. Its PMREM
    gives image-based lighting.
  * Exponential fog, a distant treeline ring, AgX tone mapping, and soft shadows that follow the player.
  * Post-processing: GTAO, bloom and AA by tier.
* **Summer grass.** Instanced grass tufts on the lawn class around the camera, swaying in the wind (Medium
  and up).
* **Winter effects.** GPU snowfall, snow sparkle on the ground, breath puffs, snow spray, the sled's track
  ribbon and boot prints.
* **Character.** `assets/character.glb` from the character agent: summer and winter outfits, 11 clips,
  walk/run clips time-scaled to the speed. The rider sits on the sled's `SledSeat`.

### Quality tiers

| tier | used by | post | AO | AA | shadows |
|---|---|---|---|---|---|
| low | — | none | — | — | none |
| medium | phones (Auto) | grade | — | FXAA | 1k PCF |
| high | desktop (Auto) | grade, bloom | GTAO ½ | MSAA 4× | 2k PCF-soft |
| ultra | Photo mode | grade, bloom | GTAO full | SMAA + MSAA | 4k |

Other quality behaviour:

* `?q=low|medium|high|ultra` forces a tier, and `?scale=0.25..1` pins the render scale (used by the tests).
* `?season=winter|summer` sets the starting season.
* Adaptive resolution runs from 0.6 to 1.0 of the full size.

## Robustness

* A watchdog shows a message if the CDN or import maps fail.
* The frame loop survives exceptions.
* A world, character or ground texture that fails to load falls back to the placeholder.
* `localStorage` access is wrapped in try/catch.
* The page makes no alert/confirm calls and no external requests besides jsDelivr.
* It respects safe areas and causes no horizontal scroll.

## Tests

`tests/run.mjs` uses Playwright with the pre-installed Chromium and SwiftShader. three and three-mesh-bvh are
served from `node_modules` through `page.route`, because the container cannot reach jsDelivr.

* **Desktop 1440×900, real keyboard.**
  * Places and spawn checks.
  * A full circuit around 3905 with W and Shift (all waypoints, at least 342° swept, never inside the
    footprint), and walking into 3905's wall is blocked.
  * The season button switches to winter.
  * The Sled button opens sled mode; A steers and R restarts.
  * A real-time scripted run with the autopilot must hit all three kickers, give more than 0.5 s of air on the
    big one, score a trick, stop before 38th St and show the summary panel.
  * Headless physics runs check the big-kicker airtime, that a pop raises the apex, that Superman scores,
    that the sled stops before the junction, and that an unfinished trick gives a wipeout and a respawn.
  * No console errors and no external requests.
* **iPhone 13 and Pixel 7, touch through CDP.**
  * No horizontal scroll and a capped DPR.
  * Joystick walk, right-side look, and a season tap.
  * Places, then Sled by tap.
  * HUD targets fit on screen and are at least 44 px.
  * The joystick steers the sled, and the POP button registers.
  * Leaving the sled works, and there are no console errors.

Screenshots go to `../docs/web_screens/`, and the results to `../docs/web_screens/results.json`.

## Measured vs artistic

The ⓘ panel shows this split.

* **Measured or documented:** terrain, footprints, street, storeys, ground cover, trees, hedges, roof
  colour and form, and the sledding line.
* **Inferred:** wall and ridge heights, and roof pitch.
* **Artistic:** facades, windows and doors on the placeholder; the kickers, berm and hay bales; sky,
  snow, lighting, sound and the people.

Only addresses are used. There is no owner or resident data.

## Known issues / limits

* **Phone load.** The art-pass worlds render about 1–2 M triangles in wide views: trees are 1.2 M of the 2.1 M
  in the file. Phones get the Medium tier, adaptive resolution (0.6–1.0), no shrub shadows, and shrub instances
  culled beyond about 85 m from the core. They have not been profiled on real hardware; only headless
  SwiftShader has been tested.
* **Pop needs the sled to stay on the ramp.** The pop window and lip launch use the `jumps.json` geometry: ramp
  from centre − L/2 to the lip at centre + L/2 along the heading. That matches the scene agent's `Jump_*`
  meshes. A sled that leaves the ramp sideways before the lip gets no forced launch.
* **Sled steering on touch** is lean-only (joystick x), with no tilt control, as specified. Tricks need a few
  tenths of a second of air, so they are hard on the small starter kicker without a pop.
* **Test timing.** Under SwiftShader the tests run at well under 1 fps, so they use simulated time
  (`__cc.simTime`) and a real-time autopilot (`__cc.autopilot`) for the scripted run. A human run on real
  hardware has not been automated.
* **Placeholder world** (used only if a world GLB is missing): facades, windows and doors are procedural.
